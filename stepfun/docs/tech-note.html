端侧 AI 推理性能优化与 seekdb 混合检索

阶跃星辰赛题 · 端侧知识库（stepfun/） · bge-small-zh-v1.5 · Transformers.js + ONNX Runtime Web · seekdb 1.4.0

方案

浏览器 Web Worker 内完成文档/查询向量化：优先 WebGPU + FP16，申请 adapter 或热身推理失败即自动降级 WASM + INT8，界面标注后端与原因。Node API 通过 seekdb-js 将 id、原文、512 维向量、元数据写入 collection；检索调用一次 hybridSearch：$contains 走 ngram 全文、knn 走 HNSW cosine、rank.rrf 在数据库内融合，客户端不拼合两路结果。稳定块 ID + upsert 保证幂等，批量写入后统一 refresh_index。

结论：WebGPU 的收益集中在批量文档向量化（约 3.8×）；batch=1 时 WASM + INT8 并不慢，查询优化应聚焦模型缓存、Worker 预热、单条 batch 与把检索下推到数据库，而不是盲目切 GPU。首次导入后的首查有 60–83 ms 冷启动，预热后稳定在约 20 ms。

工程优化

  • 导入 batch=8、查询 batch=1；模型与 ORT WASM 全部本地化，运行时不依赖 CDN。
  • 26 条向量按 32 条一批写入，整批结束只调用一次 refresh_index。
  • Web Worker 隔离推理；COOP/COEP + crossOriginIsolated 时启用 4 线程 WASM。
  • 内置分阶段计时面板，报告 P50/P95，区分首次加载与预热后性能。
  • seekdb 本地 server 模式（TCP）跨 Windows/Linux/macOS；数据落在本地 .data/seekdb。
